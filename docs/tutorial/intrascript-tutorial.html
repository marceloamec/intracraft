Guía de IntraScript

IntraScript es el lenguaje de programación de IntraCraft para simulación. Con él se programa lo que los parámetros y las reglas «Si/Entonces» no pueden expresar: encaminar palets, retener un transportador un tiempo, llevar cuentas, emitir informes.

Esta guía enseña a usarlo paso a paso, con ejemplos que se han ejecutado en el layout de demostración demo-turntable-split. Todo lo demás (cada función del editor, los miembros de cada tipo de objeto, todos los errores, secciones y direcciones) está en el manual de IntraScript.

Sintaxis de Python

Se escribe como Python: indentación, def, if, for. Cualquier editor de Python lo colorea.

Eventos

El código corre cuando algo pasa: un palet entra en un transportador, una fotocélula se activa, transcurre una hora.

Esperas

wait(2 * s) pausa una secuencia sin parar la planta.

Unidades

150 * mm y 0.25 * m / s. Mezclar longitud y tiempo es un error, no un número equivocado.

1. ¿Qué es IntraScript?

Un programa de IntraScript vive en un bloque de código: un objeto que se coloca en el plano, junto a los equipos a los que controla. Un bloque contiene:

  • Variables del bloque, que conservan su valor durante toda la simulación (un contador, una lista de pendientes).
  • Funciones, unas normales y otras convertidas en manejadores de evento con una decoración: @on_enter(Line_A) significa «cuando un palet entre en Line_A, ejecuta esta función».

El código se comprueba contra el layout antes de simular. Si un nombre está mal escrito, la simulación no arranca y se dice en qué línea.

2. Primeros pasos

Colocar un bloque de código

  1. Abre el layout demo-turntable-split.intracraft.json en IntraCraft.
  2. En la pestaña Intralogistics, en el panel Logic, pulsa Code block. Aparece una pieza violeta con las llaves { } en el plano.
  3. Muévela junto al divisor de la mesa giratoria. Su posición no afecta al código.
  4. Selecciónala: en la tabla de atributos aparece el botón Edit code….

Escribir y guardar

El editor de código colorea el texto (palabras clave, eventos en color azulado, objetos del layout en dorado, unidades en naranja), numera las líneas y comprueba el código mientras escribes. Los errores aparecen subrayados en rojo y listados debajo; las advertencias, en ámbar.

A la derecha, Names you can use lista los eventos, los objetos del layout con sus miembros, las funciones incorporadas y las unidades. Un clic copia el nombre al portapapeles.

Pulsa Ctrl+S (o Save) para guardar. Cada guardado es un paso de deshacer, como cualquier otro cambio del modelo. Un código con errores también se puede guardar, pero la simulación no arrancará hasta corregirlo.

Ejecutar

Ve a la pestaña Discrete simulation y pulsa Run. Debajo del panel de control aparece:

  • Console: lo que imprime el código, con la hora y el bloque (las últimas 200 líneas).
  • Variables of…: el valor actual de las variables de cada bloque.
  • Un error de ejecución, si lo hay, con el bloque, la línea y la hora.
0:00:00.000  Code: La simulación empieza
Code: 1 activations, 12 steps, 0 waiting

La línea de estadísticas del final cuenta las activaciones del bloque (cuántas veces se ha ejecutado una función), los pasos y las que están esperando.

3. Sintaxis

Lo que es igual que en Python

  • La indentación forma los bloques: cuatro espacios por nivel. Los tabuladores no se admiten; el editor los convierte.
  • Una línea, una instrucción. Con ; se separan dos en la misma línea; con \ al final se continúa en la siguiente.
  • Comentarios con #.
  • Mayúsculas: Roller3 y roller3 son nombres distintos.
  • Contar desde 0: el primer elemento de una lista es lista[0], el último lista[-1].
  • = asigna, == compara, != es «distinto». True, False y None se escriben con mayúscula.

Literales

TipoEjemplosNota
Entero12, -3, 1_000El guion bajo agrupa cifras
Decimal0.25, 1.5e3Punto, nunca coma
Cantidad150 * mm, 2 * sNúmero por unidad (sección 5)
Texto"Línea A", 'B'Escapes \n, \t, \"
Texto con formatof"{n} palets"Lo que va entre llaves se evalúa
Lista y tupla[1, 2], (1, "A")La lista se puede cambiar; la tupla no
Diccionario{"A": 0, "B": 0}Claves en el orden en que se añadieron

Lo que no existe en IntraScript

Para mantener la simulación determinista y segura, algunas funciones de Python no están: clases, lambda, try/except, generadores (yield), async, with, del, conjuntos (set), *args y **kwargs, y import de cualquier módulo que no sea intrascript, math o random. Si escribes una de ellas, el mensaje dice qué usar en su lugar; por ejemplo, error("…") en vez de raise.

No hace falta declarar tipos. Las anotaciones (x: int = 3) se admiten, pero solo documentan.

Variables de bloque y variables locales

Una variable escrita al principio del bloque vive durante toda la simulación y se reinicia al empezar otra. Una variable dentro de una función vive solo mientras dura esa llamada.

counted = 0          # variable de bloque: dura toda la simulación

@on_enter(Outfeed_B)
def llegada(pallet):
    global counted   # sin esto, «counted» sería una variable nueva de la función
    counted += 1
La trampa más común: si una función asigna un nombre que también es variable del bloque, Python crea una variable nueva. Por eso hay que escribir global. El editor avisa con localShadowsGlobal; si no se corrige, la simulación se para diciendo que falta global.

5. Unidades

Las cantidades llevan su unidad. Por dentro se guardan en unidades del SI, pero se muestran en mm, s, m/s, grados… como las ve un ingeniero de planta.

@on_start
def unidades():
    gap = 150 * mm              # 0.15 m
    velocidad = 0.25 * m / s
    tiempo = gap / velocidad    # 0.6 s
    print(tiempo)               # 0.6 s
    print(gap / mm)             # 150.0 (un número sin unidad)
DimensiónUnidades
Longitudmm, cm, m, km
Tiempoms, s, minute, h, day
Masag, kg, tonne
Ángulodeg, rad, rpm (velocidad angular)
Otrospercent (0.01)

Reglas

  • +, - y las comparaciones necesitan la misma dimensión. 1 * m + 20 * mm vale 1.02 m.
  • * y / combinan dimensiones: longitud / velocidad da tiempo; longitud / longitud da un número sin unidad.
  • Un número sin unidad no se suma a una cantidad: escribe gap + 2 * mm.
  • round, int y float no admiten cantidades: divide primero por la unidad, round(gap / mm).
  • Los parámetros del layout llegan con su unidad: Line_A.length es una longitud, Line_A.nominal_speed una velocidad.
Al imprimir, una cantidad muestra su número en la unidad habitual: print(Line_A.length) escribe 3000 mm. Con formato, f"{Line_A.length:.1f}" escribe 3000.0 mm.

6. Eventos

Un evento es lo que dispara una función. Se escribe como decorador, la línea que empieza por @ encima de def.

DecoradorCuándo se ejecutapallet
@on_startAl empezar la simulación, tras dar valor a las variables—
@on_finishAl terminar la simulación. No puede esperar—
@on_create(Infeed)Cuando el origen crea un paletEl palet nuevo
@on_enter(Line_A)Cuando un palet pasa a pertenecer al objetoEl palet
@on_leave(Line_A)Cuando el palet deja de pertenecer al objetoEl palet
@on_rise(Photoeye2.detected)Cuando la señal pasa a True—
@on_fall(Photoeye2.detected)Cuando la señal pasa a False—
@on_change(Line_A.run)Cuando la señal cambia, en cualquier sentido—
@every(1 * h)Cada hora simulada; start=0 * s cambia la primera vez—
@at(2 * h)Una vez, a las dos horas—
@choose_exit(Turntable)Cuando un palet centrado en la mesa necesita salida. No puede esperarEl palet

Una función puede tener varios decoradores, y un decorador puede nombrar varios objetos: @on_enter(Line_A, Line_B). Cada manejador toma los parámetros que quiera, pallet y sender, por esos nombres. Otro parámetro necesita un valor por defecto.

Orden cuando ocurren varias cosas a la vez

Con priority= se decide qué manejador va primero en el mismo instante: el de mayor prioridad, primero. Con igual prioridad, van en el orden del layout y luego en el orden en que están escritos. Un manejador se ejecuta entero antes de que empiece otro, salvo cuando espera.

7. Esperas

La espera pausa la función que la contiene. El resto de la planta sigue funcionando, y otros manejadores también.

LlamadaEfecto
wait(2 * s)Pausa 2 s de tiempo simulado
wait(0 * s)Deja pasar a lo que ya está previsto en este instante
wait_until(Line_A.occupied)Espera hasta que la condición sea cierta. Devuelve True
wait_until(cond, timeout=30 * s)Igual, pero devuelve False si pasan 30 s antes
 
@on_start
def vigilar():
    if not wait_until(Outfeed_B.count > 0, timeout=10 * minute):
        warn("Ningún palet ha llegado a B en 10 minutos")
La condición de wait_until se vuelve a mirar después de cada evento de la simulación, no una sola vez. Así que espera a condiciones, no sondees: escribe wait_until(Line_A.occupied) y no un bucle con wait(0.1 * s).

No se puede esperar en una decisión de salida (@choose_exit) ni en @on_finish: se responde en el acto.

8. Objetos del layout

Los nombres en el código

Cada equipo del layout es un nombre en el código. Si su nombre en el layout es un identificador válido, ese es el nombre (Line_A si se llama «Line A» y se cambian los espacios por guiones bajos). Si no tiene nombre, se usa su familia y su número: «Roller conveyor 100023» pasa a Roller_conveyor_100023.

La lista Names you can use del editor muestra el nombre exacto de cada equipo. Ahí está la forma correcta de escribirlo; no hace falta adivinarla.

Miembros

Cada objeto tiene los miembros de su definición en la biblioteca. Los parámetros se leen en su unidad y con nombres en minúscula y guion bajo (nominalSpeed pasa a nominal_speed).

9. Palets

Un palet es lo que crea un origen: un palet, un palet con carga o solo una carga. Dentro de un evento de palet, pallet es ese palet.

MiembroValor
idNúmero único en la simulación, en orden de creación
typeTipo de palet (EUR, IND…)
length, width, heightLongitudes del palet
load_massMasa de la carga
created_at, ageMomento de creación y tiempo transcurrido

Atributos propios

Cualquier otro nombre es un atributo que el código puede dar al palet. Se escribe y se lee como un miembro, y dura mientras el palet esté en la simulación:

@on_create(Infeed)
def etiquetar(pallet):
    pallet.destination = "B" if random.chance(0.3) else "A"
    pallet.creado = now()

Leer un atributo que el palet no tiene detiene la simulación con un mensaje que lo dice. Para comprobarlo sin riesgo: pallet.attributes.get("destination", "A").

10. Funciones y bloques

def siguiente(destino):
    """Anota un palet para el destino y devuelve la salida."""
    enviados[destino] += 1
    return Line_B if destino == "B" else Line_A
  • Las funciones se definen al principio del bloque, no dentro de otra función.
  • Un valor por defecto es un valor fijo: un número, un texto, una cantidad como 2 * s, True, False o None.
  • Se pueden llamar por nombre, con argumentos en orden o con nombre: espera(Line_A, pausa=5 * s).
  • Una función que espera hace esperar también a quien la llama.
  • Las llamadas pueden anidarse hasta 200 niveles; más se detiene con depthLimit.

Entre bloques

Un bloque puede usar las funciones y variables de otro, escribiendo el nombre del bloque (su nombre en el layout). Por ejemplo, un bloque llamado Rutas puede tener def siguiente(destino), y otro bloque puede escribir Rutas.siguiente("B") o leer Rutas.enviados. El editor conoce las funciones y variables de cada bloque y avisa si se escribe mal el nombre.

13. Línea de comandos

El mismo código se puede comprobar y ejecutar sin abrir la ventana, desde la carpeta platform del repositorio:

cargo run -p intracraft-cli -- code check ../packages/scenarios/scenarios/layouts/demo-turntable-split.intracraft.json mi_codigo.py
cargo run -p intracraft-cli -- code run   ../packages/scenarios/scenarios/layouts/demo-turntable-split.intracraft.json mi_codigo.py --seconds 10800
  • check lista los problemas del código; sale con código 1 si hay errores.
  • run simula el número de segundos indicado (3600 por defecto), escribe la consola y las estadísticas de cada bloque.
  • El archivo de código se añade al layout como un bloque llamado Code. Así un agente o un script puede probar un programa sin tocar el modelo.

14. Ejemplos completos

Cada ejemplo es un programa completo. Se han ejecutado con demo-turntable-split, y los nombres que usan son los del layout de demostración: Infeed, Turntable, Line_A, Line_B, Outfeed_A, Outfeed_B.

Ejemplo 1: el primer programa

Ya visto en la sección 2. Sirve para comprobar que el bloque está bien colocado y que la consola muestra lo que se escribe.

"""Mi primer programa: avisa cuando empieza la simulación."""
from intrascript import *


@on_start
def arranque():
    print("La simulación empieza")

Ejemplo 2: contar palets

Una variable de bloque cuenta las llegadas. Cada diez llegadas, la consola avisa. Es el patrón básico: un evento y una variable global.

"""Cuenta los palets que llegan a Outfeed_B y avisa cada 10."""
from intrascript import *

llegados = 0


@on_enter(Outfeed_B)
def llegada(pallet):
    global llegados
    llegados += 1
    if llegados % 10 == 0:
        print("Llevan", llegados, "palets en B")

Resultado de dos horas simuladas: avisos en 10, 20, 30… palets, a intervalos de unos seis minutos, según el ritmo del origen.

Ejemplo 3: encaminar por destino

Cada palet recibe un destino al nacer, y la mesa giratoria lo envía a la línea correspondiente. El 30 % de los palets van a B. Combina @on_create, un atributo del palet y @choose_exit.

"""El 30 % de los palets van a la línea B; el resto, a la A."""
from intrascript import *


@on_create(Infeed)
def etiquetar(pallet):
    pallet.destination = "B" if random.chance(0.3) else "A"


@choose_exit(Turntable)
def elegir_salida(pallet):
    if pallet.destination == "B":
        return Line_B
    return Line_A

Ejemplo 4: retener un transportador

Al entrar un palet en la línea A, el transportador se detiene dos segundos y vuelve a arrancar. Es la espera de la sección 7 aplicada a un equipo real. Compara el tiempo de tránsito con el del layout sin código para ver el efecto.

"""Cada palet detiene la línea A durante 2 s al entrar."""
from intrascript import *


@on_enter(Line_A)
def retener(pallet):
    Line_A.run = False
    wait(2 * s)
    Line_A.run = True

Ejemplo 5: informe cada hora

Un evento periódico lee las estadísticas de dos salidas y las imprime con formato.

"""Cada hora simulada, cuántos palets han llegado a cada salida."""
from intrascript import *


@every(1 * h)
def informe():
    a = Outfeed_A.stats["pallets_received"]
    b = Outfeed_B.stats["pallets_received"]
    print(f"{a:.0f} en A, {b:.0f} en B")

Ejemplo 6: vigilar que algo ocurra

Al empezar, comprueba que llega un palet a B en los primeros diez minutos. Si no, avisa. Usa wait_until con plazo.

"""Avisa si en los primeros 10 minutos no llega ningún palet a B."""
from intrascript import *


@on_start
def vigilar():
    if not wait_until(Outfeed_B.count > 0, timeout=10 * minute):
        warn("Ningún palet ha llegado a B en 10 minutos")

Ejemplo 7: limitar la entrada a una zona

Si la zona formada por el rodillo de entrada y la línea A tiene cuatro palets, el origen deja de crear hasta que haya hueco. Una función auxiliar evita repetir la suma. Es el mismo control que haría un PLC con un enclavamiento.

"""No dejar entrar más de 4 palets en la zona de la línea A."""
from intrascript import *

MAXIMO = 4
ZONA = [Infeed_roller, Line_A]


def en_zona():
    return sum([z.count for z in ZONA])


@on_create(Infeed)
def dejar_pasar(pallet):
    if en_zona() >= MAXIMO:
        Infeed.enable = False
        wait_until(en_zona() < MAXIMO)
        Infeed.enable = True
Aquí la espera está dentro de @on_create: el origen se detiene mientras el manejador espera. Es el comportamiento correcto para este control; si necesitas otra regla, la guía no cubre esa variante todavía.

Ejemplo 8: tiempo de proceso aleatorio

Cada palet que entra en la línea B tarda entre 20 y 40 segundos en procesarse, con una distribución uniforme. La consola muestra el tiempo elegido con un decimal.

"""Cada palet tarda entre 20 y 40 s en la línea B."""
from intrascript import *


@on_enter(Line_B)
def tiempo_de_proceso(pallet):
    espera = random.uniform(20 * s, 40 * s)
    wait(espera)
    print("palet", pallet.id, "listo tras", f"{espera:.1f}")

Ejemplo 9: funciones y destinos

Una función anota los envíos por destino y devuelve la salida. La mesa la llama desde @choose_exit. Al terminar, @on_finish imprime el reparto.

"""Anota los envíos por destino y devuelve la salida correspondiente."""
from intrascript import *

enviados = {"A": 0, "B": 0}


def siguiente(destino):
    """Anota un palet para el destino y devuelve la salida."""
    enviados[destino] += 1
    return Line_B if destino == "B" else Line_A


@on_create(Infeed)
def etiquetar(pallet):
    pallet.destination = "B" if random.chance(0.3) else "A"


@choose_exit(Turntable)
def elegir_salida(pallet):
    return siguiente(pallet.destination)


@on_finish
def resumen():
    print("Envíos:", enviados)

Ejemplo 10: tiempo de tránsito de cada palet

Al nacer, cada palet guarda su hora de creación como atributo. Al llegar a B se calcula cuánto tardó. Al terminar, se imprime la media. Muestra la combinación de atributos, eventos y @on_finish.

"""Mide cuánto tarda cada palet en llegar a la salida B."""
from intrascript import *

tiempos = []


@on_create(Infeed)
def nacer(pallet):
    pallet.creado = now()


@on_enter(Outfeed_B)
def llegar(pallet):
    tiempos.append(now() - pallet.creado)


@on_finish
def resumen():
    if tiempos:
        media = sum(tiempos) / len(tiempos)
        print(f"{len(tiempos)} palets, media {media:.1f}")

15. Buenas prácticas

  • Un bloque, una preocupación: uno para el encaminamiento, otro para los informes. Los bloques se hablan a través de funciones, no de variables compartidas.
  • Manejadores cortos: un evento dice cuándo; una función dice cómo. Si un manejador pasa de unas 20 líneas, reparte la lógica en funciones.
  • Funciones que se llaman desde otro bloque: escribe una línea de docstring encima.
  • Unidades en los valores, no en los nombres: gap = 150 * mm, nunca gap_mm = 150.
  • Espera a condiciones, no sondees: wait_until(…) en vez de un bucle con wait.
  • Manda sobre los equipos (run, enable, salidas) en vez de mover palets a la fuerza: así el resultado es comparable con la instalación real.
  • Prueba con la línea de comandos antes de dar por bueno un programa: code run con un tiempo corto es un buen primer contraste.

16. Preguntas frecuentes

¿Por qué no arranca la simulación?

Porque hay un error de comprobación en un bloque activo. El panel de Discrete simulation y la lista de problemas del editor dicen cuál. Si el bloque no hace falta ahora, desmárcalo como enabled = False: no se comprueba ni se ejecuta.

¿Un palet puede salir del layout desde el código?

Mover, crear o eliminar palets desde el código todavía no está en la versión 1.0. Por ahora, el código manda sobre los equipos (señales, salidas) y lee lo que ocurre.

¿Funciona en la vista 3D?

No todavía. El código corre en el módulo de simulación discreta; el módulo de física ejecuta el layout sin él.

¿Por qué la simulación da resultados distintos al cambiar un bloque?

Todos los bloques comparten la semilla, pero cada uno tiene su propia secuencia de números aleatorios. Si cambias un bloque, sus números cambian; los de los demás no.

¿Puedo usar una librería de Python, como numpy?

No. IntraScript no importa módulos externos: solo intrascript, math y random, ya integrados. Esto mantiene la simulación segura y repetible.

¿Y el editor de Python de mi equipo?

Copia platform/sim/script/python/intrascript.py junto a tu código. Con from intrascript import *, el editor completa los nombres y muestra la ayuda de cada evento y función. Ese archivo no simula nada: el programa se ejecuta en IntraCraft.
