Manual de IntraScript

Todo lo que compone la programación en IntraCraft: el lenguaje, el editor, los objetos y sus miembros, los palets, las funciones, los errores, la ejecución y las herramientas. Para aprender desde cero, empieza por la guía; este manual es la referencia completa.

Versión del lenguaje: 1. Las tablas de objetos y miembros están generadas con intracraft-cli code names a partir de la librería real, y los ejemplos se han ejecutado con intracraft-cli code run.

2. El editor

Se abre con Edit code… en los atributos de un bloque de código. Es una ventana que se puede mover y cambiar de tamaño, con tres zonas: el código (con números de línea y una línea de estado debajo), la lista de problemas y, a la derecha, los nombres que el código puede usar.

3. Primer programa

"""Mi primer programa: avisa cuando empieza la simulación."""
from intrascript import *


@on_start
def arranque():
    print("La simulación empieza")

0:00:00.000  Code: La simulación empieza

Cada línea de la consola lleva la hora de simulación y el nombre del bloque. from intrascript import * es opcional: solo ayuda a los editores de Python (sección 21).

4. Sintaxis

  • La sangría forma los bloques: cuatro espacios por nivel. Los tabuladores no se admiten (el editor los convierte).
  • Una línea, una instrucción. ; separa dos instrucciones en la misma línea; \ al final continúa la línea. Dentro de paréntesis, corchetes y llaves se puede saltar de línea libremente.
  • # empieza un comentario. Un texto justo debajo de def …: es la ayuda de la función.
  • Se distinguen mayúsculas y minúsculas. Las palabras clave de Python no pueden ser nombres.
  • = asigna, == compara, != es «distinto». True, False, None.
  • Se cuenta desde 0: lista[0] es el primero, lista[-1] el último.

Lo que IntraScript deja fuera de Python

Clases, lambda, try/except/raise (se usa error()), with, generadores (yield), async/await, del, nonlocal, funciones dentro de funciones, *args y **kwargs, conjuntos, :=, while … else y for … else, comprensiones con más de un for o de diccionario, formato de texto con % e import de módulos que no sean intrascript, math o random. Cada uno da un error de sintaxis que lo nombra y dice qué usar.

  • Claves de diccionario: números, textos, None, tuplas, objetos y palets. 1, 1.0 y True son la misma clave.

6. Unidades

Una cantidad es un número en unidades del SI con su dimensión. Los nombres de unidad son valores incorporados: 150 * mm es 0,15 m, y una cantidad dividida por su unidad da un número: gap / mm es 150.0.

NombreTamañoDimensión
mm, cm, m, km0,001 · 0,01 · 1 · 1000 mlongitud
ms, s, minute, h, day0,001 · 1 · 60 · 3600 · 86 400 stiempo
g, kg, tonne0,001 · 1 · 1000 kgmasa
deg, radπ/180 · 1 radángulo
rpm2π/60 rad/svelocidad angular
percent0,01sin dimensión
  • +, -, las comparaciones, // y % necesitan la misma dimensión: 1 * m + 20 * mm es 1,02 m; 1 * m + 2 * s detiene la simulación con unitMismatch.
  • * y / combinan dimensiones: 150 * mm / (0.25 * m / s) es 0,6 s; longitud entre longitud es un número.
  • ** solo con exponente entero sobre cantidades: 0.5 * m / s**2 es una aceleración. math.sqrt conserva las dimensiones pares.
  • round, int y float no aceptan cantidades: round(gap / mm).
  • Al mostrarse: longitudes en mm, tiempos en s, velocidades en m/s, aceleraciones en m/s², masas en kg, ángulos en grados, frecuencias por hora. print(Line_A.length) escribe 3000 mm.
  • Los minutos son minute porque min es la función mínimo; las toneladas son tonne.

Regla de Python: un nombre asignado dentro de una función es local. Para cambiar una variable del bloque se escribe global nombre al principio de la función; si falta, el editor avisa con localShadowsGlobal y la simulación se para con unboundLocal diciendo que falta global.

Arriba del bloque solo van variables, funciones, importaciones y el texto de ayuda. El código que debe ejecutarse al empezar va en una función con @on_start.

10. Funciones

def liberar(zona, pausa=2 * s):
    """Pone la zona en marcha tras la pausa y dice si tenía un palet."""
    wait(pausa)
    zona.run = True
    return zona.occupied
  • Se definen arriba del bloque, nunca dentro de otra función. Se llaman con argumentos en orden o por nombre: liberar(Line_A, pausa=5 * s).
  • Un valor por defecto es fijo: número, texto, cantidad como 2 * s, True, False o None.
  • Una función que espera hace esperar a quien la llama.
  • Hasta 200 llamadas anidadas (depthLimit).
  • Las funciones y variables de otro bloque se alcanzan por su nombre: Rutas.siguiente("B"), Rutas.enviados.
  • sorted, min, max y list.sort aceptan key= una función del bloque (no hay lambda).

11. Eventos

Una función se convierte en manejador de evento con un decorador. Cada vez que ocurre el evento empieza una activación nueva del manejador.

DecoradorCuándoObjetos que lo admitenpallet / sender
@on_startAl empezar, tras dar valor a las variables—— / —
@on_finishAl terminar; no puede esperar—— / —
@on_create(X)El origen crea un paletOrígenesel palet nuevo / el origen
@on_enter(X)Un palet pasa a pertenecer a XLos que llevan palets: transportadores, mesas, estaciones, elevadores, líneas de gravedad, sumiderosel palet / X
@on_leave(X)Un palet deja de pertenecer a XLos mismosel palet / X
@on_rise(X.señal)La señal pasa a TrueLos que tienen señales (run, running, occupied, enable, detected)— / X
@on_fall(X.señal)La señal pasa a FalseLos mismos— / X
@on_change(X.señal)La señal cambiaLos mismos— / X
@every(t, start=…)Cada t; la primera vez en start (por defecto, tras un intervalo)—— / —
@at(t)Una vez, en t—— / —
@choose_exit(X)Un palet centrado en la mesa necesita salida; no puede esperarMesas giratoriasel palet / X
  • X puede ser un nombre (Line_A), una dirección (LineaA.Line_A) o un texto con el nombre o el id del layout ("Line A"). Varios objetos a la vez: @on_enter(Line_A, Line_B). Varios decoradores en una función la atan a todos.
  • Un manejador toma los parámetros que quiera entre pallet y sender, por esos nombres; otro parámetro necesita valor por defecto.
  • priority=5 en cualquier decorador: en el mismo instante, el de mayor prioridad va primero. A igual prioridad, por orden de bloques en el layout y luego por orden de escritura.
  • Pertenecer (motor 2D): un palet pertenece al objeto donde está su cola; un transportador lo recibe cuando ha cruzado su entrada entera; un sumidero, cuando se lo lleva. El palet nuevo de un origen nace en su primer transportador: primero @on_create, luego @on_enter. Para el instante en que el frente pasa por un punto, se pone una fotocélula y se usa @on_rise.
  • Decisiones de salida: @choose_exit devuelve uno de los objetos de X.exits, o None para que decida la regla propia de la mesa. Devolver otra cosa detiene la simulación (notAnExit).

12. Esperas

LlamadaEfecto
wait(2 * s)Pausa esta activación 2 s de tiempo simulado; la planta sigue
wait(0 * s)Deja pasar primero lo que ya está previsto en este instante
wait(5)Un número sin unidad cuenta como segundos
wait_until(condición)Espera a que la condición sea cierta (si ya lo es, sigue); devuelve True
wait_until(condición, timeout=30 * s)Devuelve False si pasan 30 s antes

La condición de wait_until se vuelve a mirar tras cada evento de la simulación y en su plazo, no una sola vez. Una activación en pausa conserva todo: bucles, llamadas y variables. No se puede esperar arriba del bloque, en @on_finish ni en @choose_exit (ni en lo que estas llamen). Una espera negativa detiene la simulación (negativeWait).

13. Objetos, secciones y direcciones

Nombres

Cada equipo del layout es un nombre en el código. El nombre en el layout es su parámetro de proyecto Name; sin él, su familia y su id (Roller conveyor 100023). El nombre de código es ese nombre si es un identificador; si no, se cambian los demás caracteres por _: «Line A» es Line_A, «Outfeed (15 s)» es Outfeed_15_s. Dos objetos con el mismo nombre de código: al segundo se le añade _ y su id.

Secciones

Una sección es un grupo de objetos, como una capa: el parámetro de proyecto Section de cada componente. Normalmente está en un nivel, pero puede abarcar varios. En el módulo Diseño, el panel Section de la cinta pone la selección en una sección («Put in») o la saca («More» → «Take out»), y el panel Sections muestra u oculta cada sección en la vista activa (un filtro de vista «Section <nombre>»). Por nivel se oculta con las herramientas propias del editor.

Direcciones

QuéDirección
Objeto en una secciónLineaA.Line_A
Objeto sin secciónLine_A
Palet sobre un objetoLineaA.Line_A.MU3 (la dirección de su transportador y su nombre)
Palet fuera de la plantaMU3

En el código, una dirección completa nombra el objeto: LineaA.Line_A.run = False, @on_enter(LineaB.Line_B). Los nombres sin sección siguen valiendo. Dos objetos con la misma dirección se avisan al construir el layout. El número del palet (MU3) no cambia nunca; su dirección cambia cuando pasa al siguiente equipo.

19. Cómo se ejecuta

En el módulo Simulación discreta

  1. Ocurre un evento del motor: llega un palet, cambia un sensor, termina una estación, vence un temporizador del código.
  2. La planta se asienta en ese instante: los palets avanzan y los objetos actualizan sus señales.
  3. Se evalúan las reglas Si/Entonces.
  4. Se ejecuta el código: primero los temporizadores vencidos (wait, @every, @at), luego los manejadores de lo que cambió (palets nuevos, entradas y salidas de objetos, señales), en el orden de la sección 11, y por último cada wait_until vuelve a mirar su condición.
  5. Si las reglas o el código escribieron una señal, la planta se asienta de nuevo en el mismo instante y se repiten los pasos 3 a 5, hasta el límite de cascada.

wait(2 * s) reanuda exactamente 2 s después (al microsegundo). Las decisiones de salida se preguntan mientras la planta se asienta, cuando un palet queda centrado en la mesa.

En el módulo Simulación física

Todavía no: un layout con código ejecuta su física sin él. Está previsto ejecutar el mismo código en el ciclo del controlador (cada 10 ms).

Determinismo, límites y aislamiento

  • Mismo layout, código y semilla dan siempre el mismo resultado, en cualquier ordenador. No hay reloj, archivos ni red.
  • Límites: un millón de pasos por activación sin esperar; 200 llamadas anidadas; 1000 manejadores por instante; 100 000 elementos por lista, diccionario o texto; 10 000 activaciones esperando; 200 000 caracteres por bloque; 1000 atributos por palet; 10 000 líneas de consola (las más antiguas se pierden).
  • El código solo alcanza el modelo a través de los miembros de este manual. El intérprete está escrito en Rust seguro, sin eval: un código hostil acaba en un error, nunca en un cierre del programa.

22. Guía de estilo

  • Sigue PEP 8: cuatro espacios, líneas de unos 100 caracteres, dos líneas en blanco entre funciones.
  • Nombres: variables, funciones y atributos en snake_case; valores fijos en MAYUSCULAS; los objetos con su nombre del layout. Los sí/no empiezan por is_ o has_.
  • Las unidades van en el valor, no en el nombre: gap = 150 * mm, nunca gap_mm = 150.
  • Un manejador dice cuándo; una función dice cómo. Si un manejador pasa de unas 20 líneas, reparte la lógica.
  • Una línea de ayuda en cada función que se llame desde otro bloque. Los comentarios explican por qué, no qué.
  • Espera a condiciones (wait_until) en vez de sondear con bucles.
  • Manda sobre los equipos (run, enable, decisiones de salida) para que el resultado se compare con la instalación real.
  • Un bloque, una preocupación; usa secciones para ordenar la planta y direcciones para nombrar sin ambigüedad.

Limitar la entrada a una zona

"""No dejar entrar más de 4 palets en la zona de la línea A."""
from intrascript import *

MAXIMO = 4
ZONA = [Infeed_roller, Line_A]


def en_zona():
    return sum([z.count for z in ZONA])


@on_create(Infeed)
def dejar_pasar(pallet):
    if en_zona() >= MAXIMO:
        Infeed.enable = False
        wait_until(en_zona() < MAXIMO)
        Infeed.enable = True

25. Para desarrolladores
